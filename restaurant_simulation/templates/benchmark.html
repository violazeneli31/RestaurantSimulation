Sequential vs. Parallel

Run the same workload twice — once with one worker, once with the brigade you configured in the sidebar.

What this measures

The same set of orders is processed twice — once sequentially (one worker, no threads) and once in parallel with the brigade you set in the sidebar (chef threads, stove semaphore, three station queues, a condition variable for delivery). The speedup ratio tells you how much the parallel version helped:

speedup = time_sequential / time_parallel

Adjust the sliders to try different configurations — fewer chefs, more stoves, larger order batches — then hit Run benchmark.
